# Chronograf — Manifest  
This directory contains the **Chronograf Manifest**, the authoritative, signed index that binds together all temporal layers (`.rcg` files) into a single, verifiable specification.

The manifest is the **root of trust** for the Robot Chronograf system.  
Every robot, at boot, reads *this* file first.

---

## 🌐 What the Manifest Represents
The Chronograf Manifest acts as:

### **1. A Cryptographic Ledger**
- Stores the SHA256 hashes of all `.rcg` files  
- Ensures no temporal layer has been corrupted or altered  
- Provides a stable integrity contract between humans, robots, and toolchains

### **2. A Semantic Map**
- Lists each layer (Kernel, Channels, Topology)  
- Declares its version, semantic role, and domain bindings  
- Specifies the total number of channels and loops defined in this release

### **3. A Build Signature**
- Includes timestamps, generator tool versions, and build metadata  
- Allows reproducible builds  
- Enables 3rd-party validators to certify robot time integrity

### **4. A Temporal Constitution**
The manifest is the “single source of truth” for:
- what time *is* for the robot  
- which parts of the time system are active  
- which layer owns which responsibility  
- how future extensions must be integrated

You can think of it as:  
**_“The Constitution of Time for embodied AI systems.”_**

---

## 📘 Key File: `chronograf_manifest.rcg`
This is the canonical manifest generated by the Chronograf build system.

It contains:

- `meta_group`  
  Versioning and human-readable description

- `sources_group`  
  A list of all `.rcg` files with their expected SHA256 hashes  
  (automatically replaced by `build_chronograf.py`)

- `total_defined_channels_int`  
- `total_defined_loops_int`  
  Self-consistency metrics for validation

- `channel_primary_domain_map`  
  Maps each temporal channel to its owning domain  
  (used by schedulers and diagnostics tools)

- `runtime_contracts_group`  
  A declaration of expectations between:
  - robots  
  - runtimes  
  - integrators  
  - validators  
  - researchers

## 🧰 How the Manifest Is Generated
Use the Chronograf builder:

python spec/00_core/chronograf/tools/build_chronograf.py
This performs:

File parsing

Comment stripping (JSONC → JSON)

SHA256 hashing

Manifest assembly

Timestamp injection

Pretty-print formatting

Safe write operations

The output is written to:

swift
Copia codice
spec/00_core/chronograf/manifest/chronograf_manifest.rcg
🔍 How to Validate the Manifest
Before committing or releasing, run:

bash
Copia codice
python spec/00_core/chronograf/tools/validate_chronograf.py
This validator:

recomputes all SHA256 hashes

compares them to the manifest

ensures channel/loop counts are correct

checks for missing or extra files

verifies domain mappings

ensures structural integrity of the Chronograf

If anything is wrong → the robot must not boot.

🛡 Security & Integrity Notes
The manifest must remain immutable except when:

Updating .rcg files

Adding new channels or temporal layers

Producing an official release

Rebuilding after a signed patch

Robots in production environments should reject any unsigned or mismatched manifest.

🧬 Philosophy
The Chronograf Manifest is deliberately simple:

human-readable

machine-verifiable

version-controlled

cryptographically stable

This ensures that the definition of time is never ambiguous, never implicit, and never dependent on a specific runtime or hardware.

The manifest is the time contract.

If you want to propose new temporal channels, update semantic mappings, or extend the time ontology,
open a discussion in the repo — the Manifest will evolve with the community.
